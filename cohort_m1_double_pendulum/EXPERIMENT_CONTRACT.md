# JEPA Cohort M1 experiment contract

**Contract ID:** `m1-v1`

**Freeze date:** 2026-09-14

## Purpose

Establish a deterministic, reproducible systems-identification benchmark before any JEPA architecture or hyperparameter tuning. This contract is an educational cohort milestone and is not evidence for the parent repository's scientific claims.

## Simulator

- system: planar double pendulum;
- state: `[theta1, omega1, theta2, omega2]`;
- parameters: `m1=m2=1`, `l1=l2=1`, `g=9.81`;
- integrator: explicit RK4;
- default `dt=0.02` seconds;
- default horizon: 400 integration steps;
- angles are wrapped to `[-pi, pi)` after each step;
- no process noise or observation noise in M1.

## Dataset

Use exactly the initial-condition grid documented in `README.md` and generated by `dataset.frozen_grid()`.

Split assignment is trajectory-level and deterministic. The SHA-256 digest of the canonical initial-condition string defines bucket `digest[:16] mod 10`:

- `0..6` train
- `7` validation
- `8..9` test

No individual transition from a trajectory may appear in more than one split.

## Baselines

Before any JEPA result is considered:

1. **Persistence:** predict `state_(t+1) = state_t`.
2. **Constant velocity:** advance each angle by its current angular velocity times `dt`; keep angular velocities fixed.

## Metric

For every one-step transition, compute component-wise residuals. Angular residuals are wrapped to `[-pi, pi)`, while angular-velocity residuals are ordinary differences. Average squared residuals across the four state components and all transitions, then take the square root.

Report train, validation, and test RMSE for each baseline.

## Model-selection boundary

- architecture and hyperparameters may use train data;
- validation may be used for selection;
- test is held out until the selection rule is frozen;
- after test inspection, changes to architecture, metric, split, simulator, horizon, or preprocessing require a new contract version and must be labeled post-test.

## Minimum later JEPA comparison

A later learned model must report, at minimum:

- the exact commit SHA and config;
- parameter count;
- training seed(s);
- train and validation curves;
- validation selection rule;
- held-out test RMSE under this unchanged metric;
- persistence and constant-velocity test RMSE from the same artifact;
- failure cases and negative results.

Beating a trivial baseline is necessary for basic usefulness under this toy benchmark but is not sufficient for a scientific or general-intelligence claim.
